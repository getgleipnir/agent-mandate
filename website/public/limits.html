What it doesn’t do

A signed mandate proves who allowed what. Here is what it leaves open. The full threat model is in the spec.

It doesn’t catch bad decisions

An agent acting inside what was allowed can still be wrong. A fake invoice from an approved supplier passes.

Prompt injection inside the scope

If the agent is tricked into something the mandate allows, the check says allowed. The scope limits the damage, it doesn’t remove it.

Duplicate invoices with a new id

The same payment id is caught. The same invoice sent again with a new id, inside the limits, is not.

Skipping the check

Nothing forces anyone to run it. In shadow mode nothing is enforced by design.

A stolen signer device

Whoever holds the key can sign. Rotation and revocation help after the fact.

Who a link signer really is

A mandate link alone doesn’t identify the signer. The key has to be enrolled with someone who knows the person.

Revocation delay and trust

A check made before the revocation stands. The link status answer isn’t signed yet, so whoever controls the status host or the network could fake it.

Legal force

Whether a mandate counts as proof is open and differs by country. Nobody has tested it in a dispute yet.

Full list: spec section 11 and the mandate link notes. Found another one? Open an issue.
